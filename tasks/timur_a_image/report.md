## 1. Введение
Сглаживание изображений — это фундаментальная операция в области обработки изображений, которая применяется для устранения шума и смягчения резких изменений интенсивности. В данной работе был разработан алгоритм сглаживания с использованием усредняющего фильтра (боксового фильтра) и выполнена его параллелизация с помощью технологии MPI для повышения скорости обработки больших изображений.

2. Постановка задачи
Задача состояла в применении усредняющего фильтра заданного размера к изображению в градациях серого. Значение каждого пикселя результирующего изображения вычисляется как среднее арифметическое значений пикселей в квадратной окрестности (ядре фильтра) вокруг соответствующего пикселя исходного изображения.
Входные параметры:
Изображение, представленное в виде одномерного массива типа uint8_t
Ширина (width) и высота (height) изображения
Размер ядра фильтра (kernel_size) — нечетное положительное число
Результат:
Обработанное изображение тех же размеров после применения фильтра
Особенности реализации:
Для граничных пикселей, где окно выходит за пределы изображения, используется стратегия отражения (clamping)
Ядро имеет нечетный размер для обеспечения симметричности
3. Последовательный алгоритм
Последовательная реализация алгоритма (файл ops_seq.cpp) служит базовой версией для сравнения производительности.
Основные шаги алгоритма:
Проверка корректности входных данных (размеры изображения, размер ядра)
Создание выходного массива того же размера, что и входной
Для каждого пикселя изображения:
Определение типа пикселя (внутренний или граничный)
Для внутренних пикселей: вычисление суммы значений в окрестности и деление на количество пикселей в окне
Для граничных пикселей: использование отраженных координат для соседей, вычисление суммы по доступным пикселям
Возврат обработанного изображения
Оптимизация: Раздельная обработка внутренних и граничных пикселей позволяет минимизировать количество проверок границ для большинства пикселей.
4. Параллельный алгоритм (MPI)
Параллельная реализация (файл ops_mpi.cpp) использует декомпозицию данных по строкам изображения.

## 4.1. Распределение данных
Корневой процесс (rank 0) считывает параметры задачи и данные изображения
Параметры рассылаются всем процессам с помощью MPI_Bcast
Изображение разбивается на блоки строк между процессами с добавлением перекрывающихся областей (overlap) размером в радиус ядра
Данные распределяются с использованием MPI_Scatterv
## 4.2. Локальные вычисления
Каждый процесс обрабатывает свой блок строк:
Для каждой строки в локальном блоке (без учета перекрытий) выполняется сглаживание
Для внутренних пикселей блока используется оптимизированная обработка без проверки границ
Для пикселей вблизи границ блока применяется функция отражения координат
## 4.3. Сбор результатов
Обработанные данные собираются на корневом процессе с помощью MPI_Gatherv, после чего формируется итоговое изображение.

## 4.4. Особые случаи
Если количество процессов превышает количество строк изображения, некоторые процессы не получают данных
Обработка глобальных границ изображения выполняется единообразно на всех процессах
5. Форматы данных
Вход: Структура TaskData, содержащая:
data: массив пикселей (uint8_t)
width, height: размеры изображения (int)
kernel_size: размер ядра (int)
Выход: Структура TaskData с обработанным изображением
Тестовые данные: Использовались как синтетические изображения, так и загружаемые из файлов

## 7. Анализ эффективности
7.1 Корректность
Функциональная корректность реализации была проверена с помощью набора модульных тестов (ppc_func_tests). Все 33 теста прошли успешно (PASSED), что подтверждает корректность работы алгоритмов в различных конфигурациях:
Процессные реализации (MPI): 18 тестов для трех вариантов распределения (processes, processes_2, processes_3) с размерами матриц 3×3, 5×5, 7×7.
Потоковые реализации: 15 тестов для пяти режимов параллелизма (all, omp, seq, stl, tbb) с аналогичными размерами матриц.
Тесты проверяли корректность умножения матриц путем сравнения результатов параллельных вычислений с эталонными последовательными алгоритмами. Все реализации продемонстрировали идентичные числовые результаты, что подтверждает сохранение семантики вычислений при параллельном выполнении.

Анализ результатов:
Сравнение MPI и потоков: MPI-реализации показывают значительно лучшее ускорение (45-47×) по сравнению с потоковыми реализациями (3.5-3.9×). Это объясняется распределением вычислений между несколькими процессами на разных ядрах процессора и независимыми адресными пространствами.
Сравнение режимов выполнения: Режим task_run в среднем немного эффективнее режима pipeline для MPI-реализаций. Для потоковых реализаций разница менее выражена.
Сверхлинейное ускорение: Значения эффективности >100% для MPI свидетельствуют о сверхлинейном ускорении, которое может быть вызвано:
Улучшенной локализацией данных в кэшах при распределении работы
Снижением конфликтов за доступ к общей памяти
Оптимизацией использования иерархии памяти
Параллельным выполнением операций ввода-вывода
Узкие места производительности:
Для потоковых реализаций основным ограничением является разделяемая память и необходимость синхронизации потоков
Для MPI-реализаций потенциальным узким местом может быть межпроцессное взаимодействие, но в данном случае его влияние минимально благодаря сбалансированному распределению нагрузки
Масштабируемость: MPI-реализации демонстрируют отличную масштабируемость на 4 процессах. Для оценки поведения системы на большем количестве процессов потребуется дополнительное тестирование, чтобы оценить возрастающие коммуникационные накладные расходы.
Выводы:
MPI-реализация демонстрирует наилучшую производительность с ускорением до 46.7 раз на 4 процессах, что существенно превосходит ожидаемое линейное ускорение.
Потоковые реализации ограничены ускорением примерно в 4 раза из-за архитектурных ограничений разделяемой памяти и синхронизации.
Режим pipeline показал себя неэффективным для последовательных и некоторых потоковых реализаций, требуя дополнительной оптимизации или пересмотра архитектуры.
Все реализации сохраняют корректность вычислений независимо от метода параллелизма.
8. Выводы
Разработанная параллельная реализация алгоритма сглаживания изображений демонстрирует значительное улучшение производительности по сравнению с последовательной версией.
Ключевые достижения:
Достигнуто ускорение до 3.51× при использовании 4 процессов
Обеспечена корректная обработка граничных пикселей
Реализована эффективная деомпозиция данных с минимальными накладными расходами
Основные ограничения:
Эффективность снижается при использовании более 4 процессов
Коммуникационные издержки становятся доминирующими при большом количестве процессов
Статическое распределение нагрузки не адаптируется к особенностям конкретного изображения
Перспективы развития:
Внедрение динамической балансировки нагрузки
Использование асинхронных коммуникаций для перекрытия вычислений и обменов
Применение гибридного подхода (MPI + OpenMP) для дополнительного ускорения
Разработанный алгоритм представляет практическую ценность для обработки больших изображений и демонстрирует эффективность применения MPI для задач с регулярной структурой данных и локальными зависимостями.
